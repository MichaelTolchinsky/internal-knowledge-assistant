# New Engineer Onboarding Checklist

Before an engineer's first day, IT provisions a company laptop, an email account, and access to
the internal wiki and chat workspace - this happens automatically once HR marks the offer as
accepted, so no manual request is needed for these three items.

On day one, the new engineer's manager is responsible for requesting repository access and
adding them to the relevant team's on-call rotation tool (even if they won't be on-call
immediately) - repository access is not automatic and must be requested per-repository through
the access-management tool, same as production database access.

Within the first week, every new engineer is expected to complete the security-awareness training
module and ship a small, low-risk pull request (documentation fixes count) to become familiar
with the deployment process described in the deployment runbook - this is a soft expectation, not
a hard gate, but managers are asked to check in if it hasn't happened by day 10.

Production database access and Bedrock/AWS console access are explicitly NOT part of standard
onboarding - both follow their own separate, time-boxed request processes described in the
production database access doc and are only granted when a specific need arises, never by
default during onboarding.

A 30-60-90 day check-in is scheduled by the manager, not HR, and is meant to review progress
against onboarding goals set in the first week.
